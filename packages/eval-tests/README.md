## Scripted multi-turn cases

Existing cases need no changes. An `input` containing `prompt` and optional
`db_seed` still runs one agent turn with the existing single-turn system prompt.
To opt in to a scripted conversation, add `follow_up_prompts`:

```json
{
  "input": {
    "prompt": "Count movies released in the year I provide next. Ask me for the year first.",
    "follow_up_prompts": [
      "Use 1999.",
      "Now count only those movies with a runtime under 100 minutes."
    ],
    "db_seed": ["movies"]
  },
  "expected": {
    "llm_judge": "Check $conversation: the assistant should ask for the year before counting, then count movies released in 1999. Check $response: the final count should include only movies from 1999 with runtime under 100 minutes. Use read-only tools to verify both counts."
  },
  "metadata": {
    "name": "Refine a movie count across turns",
    "description": "Ask for a missing year, then refine the same query using conversation context."
  }
}
```

- The initial `prompt` is sent first. After each normally completed agent turn,
  the next scripted string is appended as a user message. Follow-ups are
  unconditional: they do not match on the assistant's response or require a human.
  Future replies are not shown to the model in advance.
- `follow_up_prompts` accepts at most nine non-empty strings, for ten user turns
  total. Omission and an empty array both preserve single-turn behavior.
- Only opted-in cases append a system instruction allowing clarification and
  overriding single-turn-only and no-clarification instructions. The
  database-isolation instruction is still applied to every turn.
- All turns share the same tools, temporary database, and conversation, including
  assistant messages, tool calls, and tool results. The database is seeded once
  before the conversation and dropped after the case, as for single-turn cases.
- The existing ten-step task budget is shared across the entire conversation,
  including tool-use steps; it does not reset for follow-ups. If the budget runs
  out before the next scripted user turn, the case fails with an explicit error.
  A non-`stop` finish reason keeps the existing diagnostic response and stops the
  script immediately. Model or tool execution errors retain the SDK's error
  behavior; the harness does not catch or suppress them.
- `$response` exposes the final agent turn's text, while `$conversation` exposes
  every processed user turn and its assistant/tool messages. Use `$conversation`
  in judge criteria that assess clarification or intermediate answers.
- `validateReferenceAnswer` still runs the reference answer as one standalone
  prompt and ignores `follow_up_prompts`.

The input schema generated by `pnpm run eval:generate-schemas` includes the
optional field and its bounds. Existing Braintrust datasets remain compatible;
update a dataset's input schema before adding scripted cases if it enforces the
previous schema.

## Deterministic tests

From the repository root:

```sh
pnpm exec vitest run --project unit packages/eval-tests --no-coverage
```

These tests use mocked model/tool boundaries and do not need a database, API key,
or paid model calls.
